# Базы пати Const Party Pilot

Здесь лежат базы пати — по одному файлу на пати, имя файла совпадает с
`partyId` из токена.

```json
{
  "partyId": "…",
  "name": "Клан Медведей",
  "createdAt": "…",
  "masterHash": "…",
  "tokens": [
    {
      "id": "…",
      "hash": "…",
      "charId": "…",
      "charName": "Конарх",
      "createdAt": "…"
    }
  ],
  "db": {
    "chars": [],
    "warehouse": { "stacks": [], "log": [] },
    "wishes": [],
    "sets": [],
    "schedule": { "prime": {}, "offs": [], "checklist": [] }
  }
}
```

**`masterHash` и `hash` в токенах — это SHA-256 секретной части, а не сам
токен.** Поэтому скопировать базу из репозитория и войти в пати не получится:
файла достаточно, чтобы прочитать данные, но недостаточно, чтобы получить
доступ на запись.

## Два вида доступа

**Мастер-токен** один на пати, выдаётся при создании и при перевыпуске.
Правит любого персонажа, общую казну, расписание, выпускает и отзывает
токены.

**Токен персонажа** выпускается мастером на конкретного персонажа. Видит всю
пати, правит только того, на кого выдан. Проверяется это на сервере по всему
документу целиком: сравнивается всё, кроме персонажа токена и служебных меток
«кто и когда записал».

Перевыпуск мастер-токена отзывает все ранее выпущенные токены персонажей —
у того, у кого мастер-токен увели, не должно остаться права раздавать права.

`tokenHash` в базах, созданных до разделения, — это как раз хеш
мастер-токена; он читается наравне с `masterHash` и однажды переписывается
вместе с ближайшей правкой.

## Как это устроено

Файлы создаёт и правит Worker: <https://github.com/pickmebait/lu4-party-pilot/blob/main/worker/src/index.ts>
Он же берёт токен GitHub из своего секрета — в браузерах его нет.

Каждая правка пати — отдельный коммит с ником автора в сообщении, поэтому
в истории видно, кто и когда что менял.

GitHub раздаёт ветку не мгновенно: сразу после записи чтение может вернуть
прежний файл. Поэтому Worker после записи сверяет, что чтение уже отдаёт
только что записанное, и ждёт этого не больше четырёх секунд. Пока ждёт — от
клиента, который повторяет оборванный запрос, приходит «в базе есть более
свежая версия» про его же правку.

Файлы можно править руками через GitHub, но осторожно: сервер откажет
сохранение, если версия в его копии отличается от того, что он последний раз
читал. Лучше пользоваться приложением.
