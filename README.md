# Party Pilot

Трекер экипировки пати, общей казны и хотелок для Lineage 2.

Работает как обычное веб-приложение. Код хостится на GitHub Pages, данные и
доступ — на своём сервере. Доступ выдаётся **токеном пати**, который никак не
связан с GitHub.

## Как это устроено

```
github.io            ← код приложения (статика, бесплатно)
    │  токен пати
    ▼
Cloudflare Worker    ← проверяет токен, пишет и читает базу
    │  токен GitHub хранится в секрете Worker'а, в браузер не попадает
    ▼
твой репозиторий     ← data/parties/<partyId>.json, по файлу на пати
```

Игрок открывает сайт, вводит токен — и получает общую казну, хотелки и
комплекты своей пати. Больше ничего настраивать не нужно: адрес сервера
зашит в сборку при развёртывании, поля для его ввода в приложении нет.

Создание токена = создание пати = новый файл в репозитории. Всё, что меняют
игроки, ложится в твой репозиторий: история правок, бэкапы и контроль у
тебя.

## Что умеет

**Персонажи** — 14 типов слотов (оружие, щит, шлем, нагрудник, наушники,
ботинки, перчатки, плащ, ожерелье, 2 серьги, 2 кольца, 2 браслета, реликвия,
пояс). У вещи своя метка заточки. Вещь можно передать другому персонажу в
один клик, если слот свободен.

**Общая казна** — стопки предметов с количеством. Каждое действие («положил» /
«забрал») попадает в историю с ником и временем.

**Хотелки** — список нужного с приоритетом, указанием, кто ищет и для кого.
Кнопка «Нашёл в казну» сразу кладёт предмет на склад и закрывает хотелку.

**Комплекты** — задаёшь части сета, приложение считает, сколько надето,
сколько в казне и чего не хватает.

## Как поднять своё развёртывание

**Уже развёрнуто:**

| Что | Где |
| --- | --- |
| Сайт | <https://pickmebait.github.io/lu4-party-pilot/> |
| База (Worker) | `https://lu4-party-pilot.lu4-pilot.workers.dev` |
| Базы пати | `data/parties/<partyId>.json` в этом репозитории |
| Переменная сборки | `VITE_API_URL` в Variables репозитория |

Если разворачиваешь заново — те же шаги, что были при первом запуске:

```sh
npm install
npm run cf:login     # откроется браузер — разреши доступ
```

Дальше нужен токен GitHub для самого Worker'а. Это **не** токен, который
вводят игроки, — он живёт только в секрете Worker'а и в браузерах не
появляется:

1. <https://github.com/settings/personal-access-tokens/new>
2. Repository access — **Only select repositories** → твой репозиторий
3. Permissions → Contents: **Read and write**
4. Больше ничего не выдавай
5. Вставь токен в `.dev.vars` одной строкой `GITHUB_TOKEN=github_pat_…`

Затем — **именно в таком порядке**:

```sh
npm run cf:deploy    # 1. развернуть Worker
npm run cf:secret    # 2. загрузить секрет
```

Порядок обязателен: секрет накладывается поверх последнего деплоя, и
следующий `cf:deploy` его сотрёт. Скрипт сам об этом предупреждает.

Адрес Worker'а прописывается в **Settings → Secrets and variables → Actions →
Variables** как `VITE_API_URL` — тогда сайт соберётся с готовым адресом и
игрокам вообще не нужно ничего вводить, кроме токена.

Репозиторий и каталог с базами задаются в `wrangler.toml`
(`REPO_OWNER`, `REPO_NAME`, `REPO_BRANCH`, `DATA_DIR`).

Если `VITE_API_URL` не задан, приложение покажет «Приложение не настроено»
и подскажет, что именно нужно сделать. Это лучше, чем предлагать игроку
вводить адрес, которого в рабочей сборке нет.

### Если workers.dev недоступен

`*.workers.dev` бывает заблокирован на уровне сети провайдера. Если Worker
не открывается — привяжи его к своему домену: **Workers → Routes → Add →
Custom domain**, и поправь `ALLOWED_ORIGIN` в `wrangler.toml`.

### Для разработки

```sh
npm run cf:dev       # Worker локально на :8787
npm run dev          # приложение на :5173
```

Локальный Worker работает с тем же репозиторием — правки баз попадут туда
же. Если это не нужно, укажи в `.dev.vars` другое `REPO_NAME` на свой
тестовый репозиторий.

## Как выдать доступ игрокам

1. Открой сайт и нажми **«Создать свою пати»**
2. Получи токен вида `p2p_…` — он показывается один раз
3. Скинь токен игрокам в Дискорд или чат
4. Они вставляют его на экране входа и видят общую базу

Токен потерялся — автор пати выпускает новый через ⚙ → «Сменить токен».
Старый перестаёт работать сразу, у всех, кто его сохранил.

## Безопасность

- **Токен GitHub никогда не попадает в браузер.** Он живёт в секрете
  Worker'а. Токен, который вводят игроки, — родной для приложения и ничего
  общего с GitHub не имеет.
- **В файле пати лежит только SHA-256 секретной части токена.** Скопировать
  базу из репозитория, чтобы войти в чужую пати, не выйдет: файла хватает
  на чтение данных, но не на запись.
- **Секрет токена — 160 бит** из `crypto.getRandomValues`. Перебора нет.
- **Токен хранится только в localStorage** браузера. Не отправляй его туда,
  где он засветится: скриншоты, публичные чаты.
- Сейчас токен у всех один на пати. Схема уже различает автора и участника,
  поэтому отдельный токен на игрока с возможностью отзывать — следующий шаг.

Учти: если базы лежат в том же публичном репозитории, что и сайт, любой
может их прочитать по прямой ссылке. Если это неприемлемо — укажи Worker'у
отдельный приватный репозиторий через `REPO_NAME` в `wrangler.toml`, а сайт
оставь публичным.

## Конфликты одновременной работы

Когда двое жмут «Сохранить» одновременно, второй получит отказ, а не затрёт
первого. Приложение покажет чужую версию и спросит, что оставить: принять
её или выгрузить свою в файл.

Правило на практике: правь кто-то один, остальные жмут «Загрузить».

## Справочник предметов

Справочник собирается с <https://lu4db.ru/market> — каталог предметов рынка
и вики экипировки.

```sh
npm run items:lu4db
```

Берутся два эндпоинта:

| Эндпоинт | Что даёт |
| --- | --- |
| `/api/craft-market/data` | 2029 предметов: названия, значки, рецепты крафта |
| `/api/craft-market/wiki` | 527 описаний экипировки: атака, защита, SA-эффекты, бонусы комплектов |

Два источника нужны потому, что в каталоге у большинства предметов нет ни
слота, ни типа — из-за этого половина вещей не попадала ни в один слот
экипировки. Вики эти данные восстанавливает.

**Что сохраняется целиком**, чтобы пригодилось позже:

- слот, тип, класс оружия, грейд, секция рынка, идентификатор эмулятора
- комплекты: бонусы, бонусы редкого варианта, бонусы после обработки
- оружие и броня: физ. и маг. АТК, физ. и маг. защита, прирост маны, SA-эффекты
- крафт: шанс, выход, все ингредиенты с количеством
- варианты вещи: тяжёлая, лёгкая, мантия — со своими значками и бонусами
- синонимы, требования по уровню

Слот восстанавливается по цепочке: поле источника → префикс
`equipmentId` (`w_` оружие, `h_` шлем, `nk_` ожерелье…) → секция рынка и вид
из вики → разбор названия. Рецепты, детали и ресурсы слотов не получают:
это не экипировка.

Покрытие: **587 предметов экипировки** доступны в слотах, из них 529 —
готовые вещи, остальные стартовая экипировка.

- `public/items.json` — 2029 предметов, около 800 КБ
- `public/icons/` — 1887 иконок webp, около 2.8 МБ

Список **закрытый**: предмет выбирается только из справочника, вручную по id
не добавляется. Иначе в пати появляются «Предмет #99999», которых нет ни в
игре, ни в базе.

Иконки скачиваются к нам, а не подключаются горячей ссылкой — сайт работает,
даже если lu4db.ru лежит. 18 картинок на самом источнике отдают 404, для
таких предметов показывается заглушка с первой буквой названия.

**Важно про номера.** Номер предмета — порядковый в каталоге, отсортированном
по техническому имени. Если источник обновится и появятся новые предметы,
номера сдвинутся, и базу пати придётся наполнять заново. Чтобы этого не
происходило чаще, пересобирать справочник стоит осознанно.

Поиск понимает название, техническое имя (`avadon_boots`), синонимы и
исходное название с двумя формами через звёздочку.

## Структура

```
worker/src/index.ts     Worker: проверка токенов, работа с репозиторием
wrangler.toml           репозиторий и каталог с базами
data/parties/           базы пати, по файлу на пати
src/lib/api.ts          клиент Worker'а
src/lib/config.ts       адрес базы (VITE_API_URL)
src/lib/store.ts        состояние, localStorage, сессия пати
src/lib/catalog.ts      поиск по справочнику
src/lib/derived.ts      прогресс комплектов и сводки
src/components/Login    экран входа и выпуск токена
public/items.json       справочник предметов
scripts/build-items.mjs сборка справочника из дампа
```

## Деплой на GitHub Pages

Репозиторий должен быть **публичным**: на бесплатном плане Pages не работает
с приватными. Workflow `.github/workflows/deploy.yml` собирает и публикует
сайт при каждом пуше в `main`.
