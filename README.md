# Const Party Pilot

Трекер экипировки пати, общей казны и хотелок для Lineage 2.

Работает как обычное веб-приложение. Код хостится на GitHub Pages, данные и
доступ — на своём сервере. Доступ выдаётся **токеном пати**, который никак не
связан с GitHub.

## Как это устроено

```
github.io            ← код приложения (статика, бесплатно)
    │  токен пати
    ▼
Cloudflare Worker    ← проверяет токен, пишет и читает базу
    │  токен GitHub хранится в секрете Worker'а, в браузер не попадает
    ▼
твой репозиторий     ← data/parties/<partyId>.json, по файлу на пати
```

Игрок открывает сайт, вводит токен — и получает общую казну, хотелки и
комплекты своей пати. Больше ничего настраивать не нужно: адрес сервера
зашит в сборку при развёртывании, поля для его ввода в приложении нет.

Создание токена = создание пати = новый файл в репозитории. Всё, что меняют
игроки, ложится в твой репозиторий: история правок, бэкапы и контроль у
тебя.

## Что умеет

**Персонажи** — 14 типов слотов (оружие, щит, шлем, нагрудник, наушники,
ботинки, перчатки, плащ, ожерелье, 2 серьги, 2 кольца, 2 браслета, реликвия,
пояс). У вещи своя метка заточки. Принадлежность — состав, десятка или окно.
Саб-классы: своя профессия, уровень и экипировка, до трёх на персонажа,
переключение между ветками прямо в карточке. Два вида показа: карточки в
строку (персонаж целиком) или столбец (сравнение пати, построчно).

**Расписание** — календарь с буднями, выходными и государственными
праздниками. Прайм назначается на диапазон дат, а на отдельные дни время
можно сдвинуть или прайм отменить. Расписание общее для пати.

**Общая казна** — стопки предметов с количеством. Каждое действие («положил» /
«забрал») попадает в историю с ником и временем.

**Хотелки** — список нужного с приоритетом, указанием, кто ищет и для кого.
Кнопка «Нашёл в казну» сразу кладёт предмет на склад и закрывает хотелку.

**Комплекты** — задаёшь части сета, приложение считает, сколько надето,
сколько в казне и чего не хватает.

## Как поднять своё развёртывание

**Уже развёрнуто:**

| Что | Где |
| --- | --- |
| Сайт | <https://pickmebait.github.io/lu4-party-pilot/> |
| База (Worker) | `https://lu4-party-pilot.lu4-pilot.workers.dev` |
| Базы пати | `data/parties/<partyId>.json` в этом репозитории |
| Переменная сборки | `VITE_API_URL` в Variables репозитория |

Если разворачиваешь заново — те же шаги, что были при первом запуске:

```sh
npm install
npm run cf:login     # откроется браузер — разреши доступ
```

Дальше нужен токен GitHub для самого Worker'а. Это **не** токен, который
вводят игроки, — он живёт только в секрете Worker'а и в браузерах не
появляется:

1. <https://github.com/settings/personal-access-tokens/new>
2. Repository access — **Only select repositories** → твой репозиторий
3. Permissions → Contents: **Read and write**
4. Больше ничего не выдавай
5. Вставь токен в `.dev.vars` одной строкой `GITHUB_TOKEN=github_pat_…`

Затем — **именно в таком порядке**:

```sh
npm run cf:deploy    # 1. развернуть Worker
npm run cf:secret    # 2. загрузить секрет
```

Порядок обязателен: секрет накладывается поверх последнего деплоя, и
следующий `cf:deploy` его сотрёт. Скрипт сам об этом предупреждает.

Адрес Worker'а прописывается в **Settings → Secrets and variables → Actions →
Variables** как `VITE_API_URL` — тогда сайт соберётся с готовым адресом и
игрокам вообще не нужно ничего вводить, кроме токена.

Репозиторий и каталог с базами задаются в `wrangler.toml`
(`REPO_OWNER`, `REPO_NAME`, `REPO_BRANCH`, `DATA_DIR`).

Если `VITE_API_URL` не задан, приложение покажет «Приложение не настроено»
и подскажет, что именно нужно сделать. Это лучше, чем предлагать игроку
вводить адрес, которого в рабочей сборке нет.

### Если workers.dev недоступен

`*.workers.dev` бывает заблокирован на уровне сети провайдера. Если Worker
не открывается — привяжи его к своему домену: **Workers → Routes → Add →
Custom domain**, и поправь `ALLOWED_ORIGIN` в `wrangler.toml`.

### Для разработки

```sh
npm run cf:dev       # Worker локально на :8787
npm run dev          # приложение на :5173
```

Локальный Worker работает с тем же репозиторием — правки баз попадут туда
же. Если это не нужно, укажи в `.dev.vars` другое `REPO_NAME` на свой
тестовый репозиторий.

## Как выдать доступ игрокам

1. Открой сайт и нажми **«Создать свою пати»**
2. Получи токен вида `p2p_…` — он показывается один раз
3. Скинь токен игрокам в Дискорд или чат
4. Они вставляют его на экране входа и видят общую базу

Токен потерялся — автор пати выпускает новый через ⚙ → «Сменить токен».
Старый перестаёт работать сразу, у всех, кто его сохранил.

## Безопасность

- **Токен GitHub никогда не попадает в браузер.** Он живёт в секрете
  Worker'а. Токен, который вводят игроки, — родной для приложения и ничего
  общего с GitHub не имеет.
- **В файле пати лежит только SHA-256 секретной части токена.** Скопировать
  базу из репозитория, чтобы войти в чужую пати, не выйдет: файла хватает
  на чтение данных, но не на запись.
- **Секрет токена — 160 бит** из `crypto.getRandomValues`. Перебора нет.
- **Токен хранится только в localStorage** браузера. Не отправляй его туда,
  где он засветится: скриншоты, публичные чаты.
- Сейчас токен у всех один на пати. Схема уже различает автора и участника,
  поэтому отдельный токен на игрока с возможностью отзывать — следующий шаг.

Учти: если базы лежат в том же публичном репозитории, что и сайт, любой
может их прочитать по прямой ссылке. Если это неприемлемо — укажи Worker'у
отдельный приватный репозиторий через `REPO_NAME` в `wrangler.toml`, а сайт
оставь публичным.

## Конфликты одновременной работы

Когда двое жмут «Сохранить» одновременно, второй получит отказ, а не затрёт
первого. Приложение покажет чужую версию и спросит, что оставить: принять
её или выгрузить свою в файл.

Правило на практике: правь кто-то один, остальные жмут «Загрузить».

## Производственный календарь

Праздники для раздела «Расписание» лежат файлом `src/lib/holidays-ru.json`.
Это данные isdayoff.ru в зеркальном наборе `d10xa/holidays-calendar`:
покрытие 2011–2027, внутри — праздничные дни, рабочие дни среди выходных и
сокращённые.

Почему не обращаться к isdayoff.ru прямо: его API отдаёт 403 и не присылает
`Access-Control-Allow-Origin`, поэтому из браузера он недоступен никак —
ни при каком User-Agent. Проверено прямым запросом и запросом с браузерными
заголовками.

```sh
npm run holidays   # обновить календарь
```

Обновлять стоит раз в год, обычно в декабре, когда выходит постановление
правительства о переносах на следующий год. Года за пределами файла
показываются без праздников: переносы меняет постановление, и гадать по
правилам значило бы показать 9 мая рабочим.

Справочник собран с <https://masterwork.wiki/lu4-gamma> из трёх статей:

| Статья | Что берём | Предметов |
| --- | --- | ---: |
| [Все виды оружия](https://masterwork.wiki/lu4-gamma/posts/post/793-all-weapon-types) | 16 типов, грейды NG/D/C/B/A, физическая и магическая атака, SA, редкие эффекты, бонусы заточки | 414 |
| [Все виды бижутерии](https://masterwork.wiki/lu4-gamma/posts/post/802-all-jewerly-types) | тип, маг. защита, MP, редкие и эпические бонусы | 63 |
| [Все доспехи и комплекты](https://masterwork.wiki/lu4-gamma/posts/post/803-all-armor-and-sets) | тип брони и предмета, физ. защита, MP, комплекты и их бонусы | 292 |

Итого **769 предметов**, **65 комплектов** и **587 иконок**. Всё это лежит в
`public/items.json` (около 780 КБ) и `public/icons-mw/` (около 3.2 МБ).

```sh
npm run items                 # собрать items.json и докачать недостающие иконки
npm run items:no-icons        # только items.json, иконки уже на месте
node scripts/build-catalog.mjs --refresh-icons  # заново скачать все 587 иконок
npm run check                 # проверить справочник и типы
```

### Сырые данные

| Путь | Что это |
| --- | --- |
| `data/masterwork/posts/weapons.json` | разобранная статья про оружие |
| `data/masterwork/posts/jewelry.json` | разобранная статья про бижутерию |
| `data/masterwork/posts/armor.json` | разобранная статья про доспехи и комплекты |
| `public/items.json` | собранный справочник для приложения |
| `public/icons-mw/` | иконки предметов, скачанные с masterwork.wiki |

Сборщик проверяет, что в исходниках сходятся ожидаемые количества: 414
оружия, 63 бижутерии, 292 доспеха, 65 комплектов, 172 оружия с SA, 33 общих
SA, 129 редких, 138 бонусов заточки. Если статья изменилась, сборка
останавливается, а не записывает неполный справочник.

### Что сохраняется у предмета

- **Оружие.** Двуручные мечи, двуручные топоры, двуручные посохи, парные
  мечи, парные топоры, парные кинжалы и луки занимают обе руки. У парных есть
  отдельный признак `dual`, у остальных — `twoHanded`. Копья остаются
  одноручными. У оружия с SA ровно три выбираемых варианта; общий бонус,
  который действует при любом из них, хранится отдельно в `saCommon` и не
  считается четвёртым SA. Несколько редких эффектов хранятся в `rareEffects`
  (первый дублируется в `rareEffect` для совместимости). Бонусы, которые
  открываются с заточки, лежат в `enchantBonuses`; например, у парного оружия
  это часто `+4`.
- **Бижутерия.** Тип (кольцо, серьга, ожерелье), маг. защита, MP, редкий
  эффект и эпический бонус. Эпическая бижутерия остаётся в своём слоте, а не
  превращается в отдельный слот.
- **Доспехи.** Тип брони (`heavy`, `light`, `magic`) и тип предмета (`top`,
  `bottom`, `full`, `helmet`, `gloves`, `boots`, `shield`, `accessory`).
  Цельная броня лежит в слоте верха с `fullbody: true` и занимает ещё низ.
  Щиты лежат в левой руке, аксессуары-коронки — в слоте шлема. У комплекта
  могут быть тяжёлый, лёгкий и магический варианты с одинаковым именем; они
  различаются `setId`/`setType`, а шлем может входить сразу в несколько
  вариантов.
- **Ссылки и картинки.** У каждого предмета есть `url` на карточку
  masterwork.wiki и `imageUrl` на исходную иконку. В `icon` записан локальный
  путь, поэтому приложение работает, даже если вики недоступна.

В `public/items.json` есть верхнеуровневый массив `sets`: части комплекта,
вариант, бонусы и суммарные характеристики. В пикере фильтры строятся по
типу оружия, типу брони, типу предмета и грейду. Выбранные SA и редкий эффект
сохраняются в ячейке; активный бонус заточки показывается меткой `+4` и
подсказкой.

### Иконки и обновление

Иконки качаются последовательно с паузой 140 мс, повторами и проверкой PNG.
При `--refresh-icons` файлы сначала складываются во временную папку, и только
после успешной загрузки заменяют `public/icons-mw`; если сеть оборвалась,
старый каталог остаётся на месте.

Чтобы обновить справочник, поправьте три JSON-файла в
`data/masterwork/posts/`, сохранив структуру `items`/`sets`, и запустите
`npm run items`. Если количества изменились, обновите ожидаемые числа в
`scripts/build-catalog.mjs` — сборщик специально падает, чтобы не потерять
данные молча.

## Структура

```
worker/src/index.ts     Worker: проверка токенов, работа с репозиторием
wrangler.toml           репозиторий и каталог с базами
data/parties/           базы пати, по файлу на пати
src/lib/api.ts          клиент Worker'а
src/lib/config.ts       адрес базы (VITE_API_URL)
src/lib/store.ts        состояние, localStorage, сессия пати
src/lib/catalog.ts      поиск по справочнику
src/lib/derived.ts      прогресс комплектов и сводки
src/components/Login    экран входа и выпуск токена
public/items.json       справочник предметов и комплекты
public/icons-mw/        локальные иконки предметов
data/masterwork/posts/  три разобранные статьи вики
scripts/build-catalog.mjs   сборка справочника и загрузка иконок
scripts/check-catalog.mjs   проверки справочника
scripts/check-items-ui.mjs  проверки пикера и ячеек
```

## Деплой на GitHub Pages

Репозиторий должен быть **публичным**: на бесплатном плане Pages не работает
с приватными. Workflow `.github/workflows/deploy.yml` собирает и публикует
сайт при каждом пуше в `main`.
