# Party Pilot

Трекер экипировки пати, общей казны и хотелок для Lineage 2.

Работает как обычное веб-приложение, хостится бесплатно на GitHub Pages.
Данные лежат в браузере, а общая база для всей пати — один файл
`data/data.json` в репозитории.

## Что умеет

**Персонажи** — 14 слотов экипировки (оружие, щит, шлем, нагрудник, штаны,
ботинки, перчатки, плащ, ожерелье, 2 серьги, 2 кольца, 2 браслета, реликвия,
пояс). У каждого предмета своя метка заточки. Вещь можно передать другому
персонажу в один клик, если слот свободен.

**Общая казна** — стопки предметов с количеством. Любое действие («положил» /
«забрал») попадает в историю с ником и временем, поэтому видно, кто и куда
своё перевёл.

**Хотелки** — список нужного с приоритетом (срочно / нужно / желательно),
указанием, кто ищет и для какого персонажа. Отметка «Нашёл в казну» сразу
кладёт предмет на склад и закрывает хотелку.

**Комплекты** — задаёшь части сета, приложение считает, сколько надето на
пати, сколько лежит в казне и каких частей не хватает.

## Как запустить локально

```sh
npm install
npm run dev
```

Откроется на http://localhost:5173

Сборка для продакшена:

```sh
npm run build     # результат в dist/
npm run preview   # посмотреть собранное локально
```

## Справочник предметов

В комплекте лежит демо-справочник из нескольких предметов — чтобы поиск сразу
работал. Свой собирается из дампа твоего сервера и клиента:

```sh
npm run items -- --items "D:\l2server\data\stats\items" --lang "C:\Games\L2\system\lang\ru\systemmsg.txt"
```

- `--items` — каталог с `*.xml` предметов сервера. Даёт связку `id ↔ техническое
  имя` и принадлежность к комплекту.
- `--lang` — `systemmsg.txt` из клиента. Даёт русские названия по техническим
  именам.

Результат — `public/items.json`. Поддерживаются оба формата файла с
названиями: `systemmsg.txt` и `strings-ru.xml`, а также кириллица, записанная
как `\xNN`-последовательности.

Что делать, если справочника нет совсем: предмет добавляется вручную по ID в
окне выбора. Название, которое ты введёшь, сохраняется в общей базе и видно
всей пати.

## Общая база: как это устроено

Файл `data/data.json` в репозитории — источник общих данных.

- **Чтение** идёт через `raw.githubusercontent.com`, токен не нужен: репозиторий
  публичный, и чистая статика с GitHub Pages не может держать настоящую БД.
- **Запись** идёт через GitHub REST API и требует токена.

Настройка токена (⚙ в шапке приложения):

1. Открой <https://github.com/settings/personal-access-tokens/new>
2. Repository access — только **выбери свой репозиторий** с этим приложением
3. Permissions → Repository permissions → **Contents: Read and write**
4. Больше ничего не выдавай. Ни `workflows`, ни `administration` не нужны.
5. Вставь токен в поле «Токен» в приложении

Токен сохраняется только в `localStorage` этого браузера. В репозиторий он не
попадает: там лежат только игровые данные.

### Как разрешаются конфликты

В `data.json` есть `updatedAt` и `updatedBy`. Перед записью приложение
перечитывает файл: если в репозитории версия новее твоей локальной, запись
отменяется и предлагается выбрать, что оставить. Молча перезаписать чужое
изменение не получится.

Правило на практике: **касса и хотелки ведёт один человек**, остальные смотрят
через «Загрузить». Если изменения нужны нескольким — пользуйтесь кнопками
«Выгрузить в файл» / «Загрузить из файла», это работает без токена вообще.

### Свой токен для каждого в пати

Fine-grained токен — правильный выбор для остальных участников. Один токен на
всех не нужен: каждый вставляет свой, и GitHub ведёт историю по коммитам.

<https://github.com/settings/personal-access-tokens/new>

| Поле | Значение |
| --- | --- |
| Repository access | **Only select repositories** → `pickmebait/lu4-party-pilot` |
| Contents | **Read and write** |
| Остальные права | не выдавать |

## Деплой на GitHub Pages

Репозиторий должен быть **публичным**: на бесплатном плане Pages не
работает с приватными репозиториями.

Файл `.github/workflows/deploy.yml` уже настроен — он собирает и публикует
сайт при каждом пуше в `main`.

1. Запуши репозиторий на GitHub
2. `Settings → Pages → Build and deployment → Source → GitHub Actions`
3. Через минуту сайт будет на `https://<твой-ник>.github.io/<repo>/`

## Структура

```
data/data.json           общая база пати (её и синхронизируют)
public/items.json        справочник предметов
scripts/build-items.mjs  сборка справочника из дампа
src/types.ts             доменная модель
src/lib/store.ts         состояние + localStorage
src/lib/github.ts        чтение и запись data.json
src/lib/catalog.ts       поиск по справочнику
src/lib/derived.ts       прогресс комплектов и сводки
src/components/          интерфейс по вкладкам
```

## Безопасность

- Токен живёт только в токене браузера (`localStorage`). Не клади его в код,
  не коммить в репозиторий, не отправляй в Дискорд.
- Если токен засветился в чате, в логах или в скриншоте — **отзови его** на
  <https://github.com/settings/personal-access-tokens> и выпусти новый.
- Данные игроков (ники, состав вещей) лежат в публичном репозитории. Если это
  неприемлемо — не включай синхронизацию и работай на локальных данных плюс
  экспорт/импорт файлом.
